# Pocket Option Background

Отдельное Windows-приложение на Electron для управления окном Pocket Option и его постоянной браузерной сессией.

## Текущий этап

Эта ветка развивает Electron-оболочку и добавляет экспериментальный pipeline рыночных данных, ручную разметку и алгоритм поиска похожих OTC-ситуаций. `pocket-tracker` используется как источник подтверждённых протокольных и DOM-паттернов; его Chrome API не переносятся напрямую.

### Реализовано в исходниках

- Главное окно управления открывается первым; Pocket Option автоматически не запускается.
- Постоянный Electron session partition: `persist:pocket-option-background`.
- Закрытие главного и сайта скрывает соответствующее окно; выход доступен через системный трей.
- Отдельный мини-виджет, не закреплённый поверх остальных окон.
- Локальные настройки и журнал JSONL.
- Диагностическая проверка по расписанию 5 минут.
- Проверка доступности сайта каждые 30 секунд, ограниченное восстановление и перезагрузка.
- Экспорт журналов в ZIP.
- Автоматическая проверка и загрузка обновлений через GitHub Releases; установка после подтверждения или при штатном выходе.
- Экспериментальный сбор входящих WebSocket-кадров Pocket Option через Chromium DevTools Protocol.
- Чтение каталога `updateAssets`, явная классификация OTC и отклонение неоднозначных символов.
- Инкрементальное построение свечей по десяти таймфреймам для подтверждённых OTC-активов.
- Пассивный приём OHLC-истории, которую Pocket Option отправляет для активного графика; данные без полного OHLC не превращаются в искусственные свечи.
- Локальное SQLite-хранилище: закрытые live- и полученные OHLC-исторические свечи сохраняются пакетами; последние 1000 свечей на актив/таймфрейм восстанавливаются после перезапуска.
- Отдельное окно ручной разметки с Canvas-графиком, отметками начала/входа/конца, выбором направления и экспирации; примеры сохраняются с независимыми snapshots до и после входа.
- Similarity Engine с нормализованными OHLC-признаками, поиском top-N по общей OTC-базе в рамках того же таймфрейма и защитой от будущих данных.
- Настраиваемые пороги сходства, минимум примеров/голосов и lookback; настройки сохраняются локально.
- Хронологическая walk-forward проверка на размеченных примерах с раздельным отображением точности среди сигналов и покрытия.
- Фоновый event-driven scanner: новые OTC-тиковые данные ставят актив в очередь анализа по выбранным таймфреймам; повторные решения на неизменённой закрытой свече не дублируются.
- Актуальные сигналы ранжируются без произвольных весов по сходству, голосам, согласованности и исторической результативности; список кандидатов виден в окне разметки.
- SQLite schema v4 decision journal: сохраняются сигналы и отказы, настройки, совпадения, голоса, входные свечи и версия алгоритма; журнал обновляется в окне разметки.

## Важные ограничения текущей ветки

1. Пользователь входит в Pocket Option вручную. Приложение не запрашивает и не хранит пароль.
2. Баланс читается отдельным DOM-адаптером по селекторам, которые используются в текущем коде `3.6.0_0/inject.js`. Селекторы сайта могут измениться; если структура сайта изменилась, статус останется «нет свежих данных», а не покажет выдуманный баланс.
3. Переключение DEMO/REAL выполняется навигацией на известные маршруты кабинета и считается успешным только после подтверждения режима и баланса адаптером. Маршрут REAL и подтверждение нужно проверить на реальном аккаунте перед использованием.
4. Автоматическая торговля и выставление сделок пока не реализованы. Scanner анализирует рынок и журналирует решения, но не нажимает кнопки UP/DOWN и не управляет открытыми позициями.
5. WebSocket capture подтверждён mock-тестами и Windows CI, но live end-to-end работа на реальном Pocket Option ещё не подтверждена. Фактическое покрытие всех OTC-пар зависит от того, какие активы сервер передаёт в потоке.
6. Исторические OHLC-события принимаются пассивно от активного графика. Это не гарантирует глубокую историю для всех пар одновременно.
7. Процент сходства — экспериментальная структурная метрика, не вероятность выигрыша. Walk-forward evaluator реализован, но его нужно запускать на реальной пользовательской выборке и оценивать статистическую устойчивость.
8. Ранжирование сигналов и изолированный helper планирования торговых намерений (pause/лимит/дедупликация) реализованы и протестированы. Но helper пока не подключён к живому scanner/ledger; реальные слоты открытых сделок, multi-pair исполнение, контроль экспозиции и статистика P/L ещё не реализованы.
9. SQLite использует встроенный `node:sqlite`; schema migrations, decision journal и Electron runtime smoke test проверяются в Windows CI.

## Запуск для разработки

Требуется Node.js LTS и Windows 11.

```powershell
cd Pocket-Option-Background
npm install
npm run check
npm start
```

Сборка установщика:

```powershell
npm run dist
```

Публикация обновления: увеличить `version` в `package.json`, отправить тег `vX.Y.Z`. Workflow `.github/workflows/release.yml` соберёт Windows NSIS установщик и опубликует GitHub Release с метаданными electron-builder (`latest.yml`). Установленная программа проверяет обновления после запуска и каждые 6 часов, автоматически скачивает найденную версию.

## Хранение данных

Профиль сайта, авторизация и cookies хранятся в Electron persistent session. Настройки и журналы — в каталоге userData приложения. Удаление этих данных удалит сохранённую авторизацию.
