# ADR-001: Хранилище рыночных данных — предложение

**Статус:** предложено, не утверждено  
**Дата:** 2026-11-20  
**Область:** Pocket Option Background / будущий Pocket Tracker

## Контекст

Текущий MarketDataStore — ограниченный in-memory прототип. Он подходит для первичного наблюдения за WebSocket-потоком, но теряет данные при перезапуске. Следующим этапам потребуются:
- свечи нескольких активов и 10 таймфреймов;
- каталог и метаданные инструментов;
- разметка свечей/событий и заметки;
- воспроизводимые snapshots решений и версия алгоритма;
- в дальнейшем — журнал сигналов и результаты сделок;
- миграции, backup/restore и проверяемая целостность.

Хранилище должно работать локально, без внешнего сервера и без записи логинов, паролей, cookies или токенов Pocket Option.

## Рассмотренные варианты

### A. SQLite через better-sqlite3 — рекомендуемый вариант

**Плюсы**
- SQL-запросы, индексы и составные ключи подходят для выборок по asset/timeframe/time.
- Транзакции подходят для атомарного сохранения свечей, меток и snapshots.
- Один локальный файл упрощает резервное копирование и перенос профиля.
- Можно мигрировать схему через таблицу schema_migrations.

**Минусы и риски**
- Это native Node module: Electron использует собственный ABI, поэтому модуль требуется пересобирать под версию Electron. Официальная документация Electron описывает необходимость rebuild; документация electron-builder также предупреждает об упаковке native binaries.
- Синхронный API нельзя вызывать длинными пачками в Electron main thread: операции БД следует вынести в Worker Thread или отдельный процесс.
- Нужно проверить Windows x64 packaging, runtime loading и asarUnpack для native binary.

**Предлагаемая реализация**
- Файл: <userData>/market-data.sqlite.
- Один владелец соединения — DB worker; main process общается с ним через узкие типизированные сообщения.
- Включить foreign keys, WAL, busy timeout и транзакционные batch inserts.
- Ключ свечи: (asset, timeframe_sec, open_time_ms).
- Таблицы первого этапа: schema_migrations, assets, candles, annotations, decision_snapshots.
- Тики хранить только при явной необходимости; по умолчанию строить и сохранять OHLC, чтобы не раздувать базу.
- Backup выполнять штатным SQLite backup-механизмом; не копировать активный файл без учёта WAL.

### B. SQLite/WASM через sql.js

**Плюсы**
- Нет native addon и ABI rebuild.
- Упрощается Windows packaging и установка.

**Минусы и риски**
- База живёт в памяти и для сохранения экспортируется в файл; частые большие экспорты могут быть дорогими.
- Нужны собственные правила атомарной записи, блокировки и восстановления после аварийного завершения.
- При большом объёме свечей расход памяти может быть заметным.

Подходит, если запрет native modules важнее удобства постоянной записи.

### C. JSONL/файлы по дням

**Плюсы**
- Нет сторонней зависимости; просто отлаживать и экспортировать.
- Хорошо подходит для append-only журналов.

**Минусы и риски**
- Сложные выборки по asset/timeframe потребуют загрузки/индексации файлов.
- Обновление/исправление свечи и атомарная запись нескольких связанных сущностей сложнее.
- Миграции и согласованность между свечами, метками и snapshots придётся реализовывать самостоятельно.

Подходит для логов, но не рекомендуется как основное хранилище свечей и связанных сущностей.

### D. Встроенный node:sqlite

В Node.js 22 модуль node:sqlite уже доступен без прежнего experimental flag, но в ветке Node 22 остаётся экспериментальным. Для стабильной пользовательской сборки это пока не рекомендуемый production-контракт.

## Рекомендация

Выбрать **SQLite через better-sqlite3 с DB worker**, если допустим native module и отдельный шаг проверки ABI/упаковки. Если native dependencies нежелательны, запасной вариант — sql.js с явным измерением стоимости экспорта/сохранения.

Не внедрять БД до утверждения варианта. Сначала сделать spike на текущей Windows CI: установка, rebuild для Electron 45.3.4, чтение/запись в worker, упаковка NSIS, запуск собранного приложения и backup/restore.

## Критерии приёмки spike

- [ ] npm install и rebuild проходят на Windows x64 для Electron 45.3.4.
- [ ] NSIS build включает native binary корректно.
- [ ] Упакованное приложение открывает БД и выполняет транзакцию без блокировки UI.
- [ ] Crash/restart не оставляет частично записанный batch.
- [ ] Backup/restore подтверждён на тестовой БД.
- [ ] Есть миграция v1 и тест её повторного запуска.
- [ ] Нет секретов аккаунта в БД и резервных копиях.
