# Память проекта Pocket Option

Этот каталог — долговременный источник проектного контекста. Перед любой задачей прочитать этот индекс и связанные документы, затем сверить факты с актуальным кодом.

## Приоритет источников
1. Текущий исходный код основного репозитория — истина о фактической реализации.
2. REQUIREMENTS.md — требования, согласованные пользователем.
3. ARCHITECTURE.md и DECISIONS.md — архитектура и решения.
4. IMPLEMENTATION_PLAN.md, KNOWN_ISSUES.md и TESTING.md — статус работ, риски и проверки.
5. Вторичный pocket-tracker — справочник существующих решений, не спецификация целевой архитектуры.

Если код и документация расходятся, не скрывать расхождение: проверить код и обновить документацию.

## Документы
- PROJECT_CONTEXT.md — цель, репозитории и принципы работы.
- REQUIREMENTS.md — согласованные требования.
- ARCHITECTURE.md — текущая и целевая архитектура.
- DECISIONS.md — решения и открытые вопросы.
- IMPLEMENTATION_PLAN.md — этапы реализации.
- KNOWN_ISSUES.md — риски и непроверенные предположения.
- TESTING.md — проверенные и непроверенные сценарии.

## Рабочий протокол
Перед изменениями:
1. Прочитать память и актуальные файлы, затрагиваемые задачей.
2. Проверить ветку, последние изменения и существующие тесты.
3. Сверить задачу с требованиями и решениями.
4. Для архитектурных изменений описать варианты, последствия и риски; не менять требования без разрешения.
5. Не переносить Chrome APIs в Electron механически.

Во время работы:
- Делать небольшие логические изменения.
- Не заявлять о готовности без проверки.
- Не ослаблять защитные настройки Electron.
- Не включать реальные сделки без отдельного согласования и защит.
- Не использовать будущие данные в признаках до точки входа.
- Не смешивать ручные примеры и сделки бота.

После изменений:
- Выполнить проверки и записать точные результаты.
- Обновить память вместе с кодом.
- Указать, что не удалось проверить.
- Не сохранять пароли, cookies, токены и приватные финансовые данные в Git.

Статусы: Согласовано / Предложение / Открытый вопрос / Реализовано. Наличие кода само по себе не подтверждает статус «Реализовано».
