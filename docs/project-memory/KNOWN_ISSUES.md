# Известные проблемы и риски

## Подтверждено источниками
1. Основное Electron-приложение 0.1.1 включает оболочку управления и экспериментальное ядро рыночных данных/анализа; брокерский торговый исполнитель и автоторговля не подключены.
2. npm run check — синтаксическая проверка, не интеграционный тест.
3. Запуск и сборка на Windows в этой сессии не подтверждены.
4. DOM-селекторы баланса/торговых элементов могут измениться.
5. WebSocket-каталог активов не доказывает одновременное исполнение.
6. executeTrade() в описании расширения управляет текущим торговым DOM.
7. modules/* исполняются в main process и имеют его полномочия; sandbox отсутствует.
8. window.postMessage требует строгой проверки source/origin/schema.
9. В архитектуре расширения упомянут HMAC-секрет в JS; клиентский встроенный секрет нельзя считать секретным.
10. Телеметрия расширения может содержать финансовые данные; при переносе нужно пересмотреть согласие, минимизацию и хранение.
11. Закрытые свечи и каталог теперь сохраняются в SQLite; незакрытые свечи остаются в RAM до закрытия. Windows runtime smoke test и live recovery ещё не подтверждены.
12. CDP capture и SQLite store проверены unit-тестами с mock debugger/Node runtime, но не на живом Electron/Pocket Option.
13. OTC-фильтр теперь использует updateAssets и явный суффикс `_OTC`; live-каталог и фактические названия ещё не проверены на текущем Pocket Option. Символы без маркера и с неоднозначным alias намеренно отклоняются.
14. Глубокая история не загружается по запросу для всех активов: MarketDataHub строит свечи из поступающих тиков и пассивно принимает OHLC history events, когда их передаёт активный график.
15. При уже подключённом Chromium debugger capture переходит в unavailable, не отключая чужой debugger.
16. `node:sqlite` — Release Candidate в Node 24.22.3; при изменении версии Electron/Node нужно повторять runtime smoke test.
17. SQLite DatabaseSync выполняет синхронные операции в main process. Пакетная запись снижает частоту блокировок, но влияние на UI под реальной нагрузкой не измерено.
18. Рыночный кэш ограничен 1000 свечами на актив/таймфрейм; глубокая история должна запрашиваться отдельно, а пользовательские размеченные примеры должны сохранять собственные snapshots, чтобы не зависеть от очистки кэша.

16. Similarity Engine — первая техническая версия: weighted MAE по нормализованным OHLC-признакам. Процент сходства не откалиброван на out-of-sample выборке и не является вероятностью выигрыша. Перед автоторговлей нужна проверка на пользовательских данных, walk-forward validation и фиксация версии формулы.
17. Similarity Engine использует до 10 000 самых новых примеров выбранного таймфрейма; глубокая история сверх лимита не участвует в текущем поиске.
18. Фоновый scanner теперь анализирует активы, для которых приходят OTC-тиковые данные, по выбранным таймфреймам и пишет решения в SQLite. Живой end-to-end прогон на Pocket Option ещё не подтверждён; scanner зависит от реального наличия закрытых свечей и выбранного набора таймфреймов.
19. Автоматические сделки, реальный контроль открытых позиций, multi-pair execution и связь торговых результатов с решениями алгоритма не реализованы. Отдельный `trade_results` хранит наблюдаемые закрытия брокера и считает P/L по измерениям, но поток может включать ручные сделки и не является чистой статистикой бота. Добавлен и протестирован чистый trade intent coordinator (pause/disabled/лимит/ранжирование/дедупликация на бар), но он пока не подключён к ledger и execution adapter.

## Не проверено
- Устойчивость соединения при скрытом окне, сне Windows и сетевых обрывах.
- Актуальность URL DEMO/REAL для всех регионов и аккаунтов.
- Точность DOM-адаптера на текущем сайте.
- Полнота свечей по всем OTC-парам.
- Фактическое поведение CDP Network.webSocketFrameReceived на текущем Pocket Option и Windows Electron 45.3.4.
- Достаточность лимитов 150 активов × 1000 свечей на серию для реального числа активов/частоты тиков.
- Исполнение по неактивной паре.
- Прибыльность алгоритма поиска похожих ситуаций.
- Работа установщика и обновлений на чистой Windows.

README/package.json/User Guide указывают 0.1.1; Developer Guide ещё может содержать старую версию 0.1.0. При изменениях синхронизировать документацию.

## Предосторожности
- Не хранить секреты и приватные финансовые данные в Git.
- Не отправлять REAL-сделки без отдельного разрешения и защит.
- Не выполнять быстрое переключение пары + клик без проверки фактического инструмента.
- Не включать post-entry признаки в поиск.
- Не смешивать DEMO и REAL без явной маркировки.

20. DecisionScanner пока использует прямой перебор сохранённых примеров при каждом новом сигнале; на больших датасетах и большом количестве OTC-пар потребуется индекс/кэш признаков и нагрузочные тесты.
21. Фоновый scanner не запускается до открытия Pocket Option и подключения CDP WebSocket capture; отсутствие потока не должно интерпретироваться как отсутствие рыночных сигналов.


## Дополнения после реализации ранжирования
- Актуальные сигналы теперь ранжируются лексикографически без произвольных весов: среднее сходство, голоса за направление, согласованность голосов, историческая win rate. Ранжирование не исполняет сделки и не заменяет лимит открытых позиций.
- Список ранжированных сигналов находится в памяти процесса и исчезает после перезапуска; исторические решения сохраняются в SQLite. Восстановление списка актуальных кандидатов из БД пока не реализовано.

- Исторические price-only ряды Pocket Option (`[timestamp, price]`) не дают OHLC high/low и поэтому пропускаются; для разметки нужны полные OHLC бары либо live-тики, из которых можно построить свечи.
- В live-событиях без timestamp время фиксируется по моменту получения WebSocket кадра. Это соответствует fallback в `pocket-tracker`, но точность времени зависит от сетевой задержки.

22. `trade-coordinator.js` пока является изолированным planner: pause/slot-limit/dedup/ranking протестированы отдельно, но он не подключён к live scanner и не видит реальные pending/open positions. Это не означает, что автоторговля готова.

23. В текущей официальной публичной оферте Pocket Option указано, что результат операции может быть отменён/пересмотрен при использовании неавторизованного bot software (раздел Trading Operations Execution): https://pocketoption.com/en/public-offer/. До live/REAL execution требуется проверить актуальные условия и разрешённость автоматизации; техническая возможность не означает разрешение.
